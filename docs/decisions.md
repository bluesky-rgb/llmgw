# 设计决策记录

每条记录写清楚当时的背景、选择和代价。以后回头看为什么这么做，或者面试时被问到“为什么”，都能在这里找到答案。

---

## ADR-001：v0.1 使用 cpp-httplib，而不是 Drogon 或 Boost.Beast

**背景**：第一个版本的目标是尽快做出一个能跑、能演示、容易编译的网关。

**选择**：使用 cpp-httplib 和 nlohmann/json，两个都是纯头文件库，由 CMake FetchContent 自动下载，除 OpenSSL 外没有系统依赖。

**代价**：cpp-httplib 是阻塞模型，一个连接占用一个线程。网关的典型负载是大量长时间的流式连接，这会让最大并发流数受线程数限制（`listen.threads`）。

**缓解**：`Gateway` 用 pimpl 封装，httplib 不出现在头文件中。以后换成异步框架时，`main.cpp`、配置和测试都不需要改。

## ADR-002：流式请求先拿到上游状态码，再决定客户端的状态码

**背景**：最简单的实现是立刻给客户端返回 `200 text/event-stream`，然后再去请求上游。但这样一来：
- 上游返回 400（比如参数错误）时，客户端只能收到 200 加一条错误事件，SDK 不容易处理；
- 一旦响应头发出，就没法再透明地切换到别的上游。

**选择**：上游请求放在独立线程中执行，通过 `StreamChannel`（互斥锁 + 条件变量 + 队列）和响应线程通信。响应线程先等上游的**响应头**到达：
- 如果上游返回 5xx/429，或者连接失败，工作线程直接换下一个目标，客户端完全感知不到；
- 拿到最终状态码后，非 2xx 的响应整体转发；2xx 的响应进入分块输出，边收边发。

**代价**：每个流式请求多一个线程，还有一次跨线程的数据拷贝。和网络延迟相比，这点开销可以忽略。

## ADR-003：只在第一个字节之前做故障切换

**背景**：流式输出到一半时上游断开了，要不要切到另一个上游重新生成？

**选择**：不切换。在流的末尾追加一条 `data: {"error": ...}` 事件，然后结束。

**理由**：客户端已经收到了一部分内容，换一个模型重新生成会得到另一段文字，拼起来是错的。是否重试应该由客户端决定。

---

## ADR-004：哪些错误可以重试

**选择**：连接失败、超时、HTTP 5xx 和 429 会切换到下一个目标；其他 4xx 直接返回给客户端。

**理由**：400/401/404 等是请求本身的问题（参数错误、模型名错误、密钥无效），换一个上游大概率还是失败，只会白白增加延迟和费用。

---

## ADR-005：客户端断开后尽快停止读取上游

**选择**：分块输出时一旦写入客户端失败，就设置 `cancelled` 标记；上游线程在下一次收到数据时检查这个标记并中止请求。

**理由**：大模型按输出 token 收费。用户关掉页面以后，如果还在继续读取上游，就是在白花钱。

**已知不足**：如果上游一直不发数据，上游线程要等到 `read_timeout_seconds` 才会退出。以后改成异步 I/O 后可以立即取消。

**后续**：v1.0 的协程方案已实现“客户端断开后立即取消”，任意阶段都在 1 ms 内取消上游，见 ADR-006 和 [任务 0.6 的验证记录](tasks/0.6-coroutine-demo.md)。原型在“首字前断开”时其实完全不会取消，上游会把整段生成跑完——比这里写的“已知不足”更严重。

## ADR-006：G1：继续使用 Asio + Beast + C++20 协程

**日期**：2026-11-21（关口 G1，原计划 11/29，提前完成）

**背景**：v1.0 的并发模型是“每核一个线程 + 每条连接一个协程”（[design.md](design.md) 第 5 节）。候选实现有两个：Asio + Beast + C++20 协程，或 Drogon。G1 的判断标准（[roadmap.md](roadmap.md)）是：支撑 5000 条以上的并发流、每条流内存不超过 100 KB、代码能读懂能讲清楚。满足就继续用 Asio，否则评估 Drogon。

**证据**（任务 0.6 的 demo，任务 0.7 的压测，详见 [benchmark.md](benchmark.md)）：

| G1 标准 | 结果 |
|---|---|
| ≥ 5000 条并发流 | ✅ 单核 9000 条流全部成功（本机上限） |
| ≤ 100 KB/流 | ✅ 约 37 KB，不随规模增长 |
| 代码能读懂、能讲清楚 | ✅ 约 500 行；核心转发逻辑约 130 行；没有回调、没有锁 |

另外，与原型 v0.1 相比：客户端断开后取消上游从“最长不取消”变为 1 ms 以内；同样 1000 条流，每块 CPU 是原型的 1/2.7、内存是 1/2.3，并且不需要预先配置线程数。

**选择**：**继续使用 Asio + Beast + C++20 协程**，不评估 Drogon。

**理由**：
- 三项标准都满足，并且留有余量
- 协程的 `||` 竞速让“客户端断开、超时、上游数据”的取消逻辑写在一个地方，这正是网关最核心、最容易出错的部分。Drogon 的回调式接口做同样的事情需要更多状态
- Asio 让我们直接控制 socket、定时器和线程模型；压测中发现的两个问题（fd 表扩容、TIME_WAIT）都需要这种底层控制才能定位和解决

**代价**：
- Boost 是较大的依赖（只构建 asio、beast 及其依赖，约 50 个库）；需要在漏洞检查中处理按整个 Boost 仓库匹配的误报（已登记 OSV-2024-112）
- HTTP 服务端的功能（路由、请求体解析等）要自己组装，Drogon 现成提供。llmgw 的路由很简单，可以接受
- C++20 协程的调试体验不如同步代码；用统一的 `as_tuple(use_awaitable)`（错误码而非异常）和 sanitizer 回归来控制

**正式实现必须遵守的结论**（来自 demo 和压测）：
1. **竞速放在“一个请求”这个粒度上，而不是“一个数据块”**。每块竞速一次的开销是搬数据本身的 8 倍以上
2. **会变化的超时（空闲超时）用惰性定时器**：数据到达时只记录时间，到期时再判断是否顺延
3. **缓冲区里已有的数据先解析，凑满再写**，不要每解析一个上游分块就写一次
4. **启动时、创建线程之前，把 fd 表预扩容到上限**。否则建连高峰期每跨过一个 2 的幂就卡约 10 ms
5. **连接池是必要条件**：没有连接池，每秒 470 个请求持续一分钟就会耗尽到同一个上游的临时端口
6. **事件循环延迟要作为指标**（`llmgw_event_loop_lag_seconds`）。本次定位卡顿全靠 demo 里的探针

## ADR-007：core 的两个第三方依赖：tl::expected 与 Asio 的 awaitable

**日期**：2026-11-21（任务 0.4）

**背景**：设计文档约定“可能失败的操作返回 `std::expected<T, Error>`”，异步接口返回 `asio::awaitable`。core 原本的定位是“不依赖任何第三方库”。

**问题 1：`std::expected` 在我们的工具链上不可用。** 实测：

| 编译器 | `std::expected` |
|---|---|
| GCC 13，C++20 | ❌ 需要 C++23 |
| GCC 13，C++23 | ✅ |
| Clang 18 + libstdc++ 13，C++23 | ❌ libstdc++ 要求的 concepts 版本高于 Clang 18 的声明，`<expected>` 被禁用 |

CI 的 clang-tidy 使用 Clang 18（Ubuntu 24.04 默认），所以即使升级到 C++23 也不能用。

**选择 1**：使用 **tl::expected v1.3.1**（CC0 许可、单头文件、接口与 `std::expected` 一致），通过别名 `llmgw::Result<T>` 和辅助函数 `llmgw::fail()` 使用，**代码中不直接写 `tl::`**。

| 备选 | 为什么不选 |
|---|---|
| 升级到 C++23 + Clang 19 | Ubuntu 24.04 默认工具链不能编译，用户从源码构建的门槛提高 |
| 自己写 `Result<T>` | 约 200 行容易出错的模板代码（移动语义、`and_then` 等），维护成本高于一个成熟的单头文件库 |

**问题 2：core 要定义异步接口**（`ResponseStream::next()` 等），G1 选定 Asio 后，返回类型只能是 `asio::awaitable`。

**选择 2**：core 依赖 Boost.Asio，但**只使用 `awaitable` 一个类型**，集中在 `task.h` 的别名 `Task<T>` 中；其他头文件只写 `Task`。

**代价**：
- 默认构建开始下载 Boost（约 100 MB）。CI 按依赖清单缓存 `.deps`，同一份清单只下载一次
- 多一个依赖 tl::expected，纳入漏洞检查（`tools/check_vulns.py`）

**迁移条件**：最低工具链支持 `std::expected` 时（比如 Clang ≥ 19，或换用 libc++），只修改 `result.h` 中的别名；调用代码不需要改动。
